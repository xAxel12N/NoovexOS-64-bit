LOC means raw `wc -l` of the .c/.h files, comments included. License rule from CONTEXT.md: the code must be GPLv3-compatible. In Linux, `GPL-2.0` (no suffix) means GPL-2.0-only.

Existing NoovexOS port: the RTL8821CE driver is a compact hand port, not the rtw88 core. It is `drivers/net/wifi/rtw8821ce.c` (797 lines), `rtw_efuse.c` and `rtw_sec.c`, plus tables in `rtw_tables.h`, generated by `tools/wifi-tables/rtwgen.c` from `RTW{MAC,BB,AGC,RFA}.TXT`. The firmware ships as `assets/firmware/rtw8821c_fw.bin`, embedded by `build.sh` with `ld -r -b binary`. xHCI already has per-class static control/bulk helpers (`xh_ctrl`, `xh_bulk`, `usn_ctrl`). There is no generic USB driver API header.

Calibration:
- 8821C: `phy_calibration = do_iqk`. Firmware IQK through `rtw_fw_do_iqk` (H2C packet `H2C_PKT_IQK` = 0x0E, fields CLEAR/SEGMENT_IQK).
- 8822B: `phy_calibration = rtw8822b_do_iqk`. Sends `rtw_fw_do_iqk` with clear=0, segment=0. Then polls RF path A reg `RF_DTXLOK` (0x08) for `0xabcde` (300 x 20 ms), writes it back to 0, then checks fail masks and may reload. No DACK/DPK. This is the 8821C model plus path B.
- 8822C `phy_calibration`:
  1. `rfk_power_save(false)`
  2. `do_gapk`: TX gain-gap K, done in the driver over BB/RF registers. It is wrapped in `rfk_handshake`: wait for BT IQK idle (`REG_PMC_DBG_CTRL1` `BITS_PMC_BT_IQK_STS` == 0, up to 600 ms), then H2C cmd `H2C_CMD_WIFI_CALIBRATION` (0x6d) via `rtw_fw_inform_rfk_status(start)`, then poll `REG_ARFR4` `BIT_WL_RFK` == 1.
  3. `do_iqk`: `rtw_fw_do_iqk` with clear=1, then poll `REG_RPT_CIP` (0x2d9c) == 0xaa (`IQK_DONE_8822C`), 20 ms-300 ms, then write `REG_IQKSTAT` (0x1b10) = 0.
  4. `do_dpk`: digital predistortion, done in the driver. It uses BB "one-shot" commands via `REG_NCTL0` and polls 0x2d9c == 0x55 or `REG_STAT_RPT` bit31, using the dpk_* tables. Runs per path.
  5. `rfk_power_save(true)`.
- 8822C DACK: `rtw8822c_rf_dac_cal`, run from `rtw8822c_rf_init`, which `phy_set_param` calls (line 1909). It first tries `dac_cal_restore`, else runs the full ADC/DAC IQ search on both paths. `rf_init` then runs `rf_x2_check`, `thermal_trim`, `power_trim`, `pa_bias`.
- 8822C runtime: `dpk_track` and `pwr_track` (`do_lck` when `rtw_phy_pwrtrack_need_lck`), plus `cfo_track`.
- 8822C RX phy-status parsing (`query_phy_status_page0/1`) and `set_channel` (bb + `rtw_set_channel_mac` + rf + `toggle_igi`) are chip-specific. 8822B has its own versions too.

## 3. Builder facts: rtw88 USB (usb.c, rtw8821cu.c)

License: `usb.c`, `usb.h` and `rtw8821cu.c` are all `GPL-2.0 OR BSD-3-Clause`; rtw8821cu.c also has MODULE_LICENSE("Dual BSD/GPL"). Size: usb.c 1406 lines, usb.h 103, rtw8821cu.c 62. The chip code is shared with PCIe (`rtw8821c_hw_spec` is the driver_info), so 8821CU reuses the existing NoovexOS 8821C logic. Register I/O, the TX/RX descriptor transport and firmware download change.

USB IDs matched with interface class/subclass/protocol 0xff/0xff/0xff:
- 8821CU: 0bda:2006, 8731, 8811, b820, b82b, c80c, c811, c820, c821, c82a, c82b; 2001:331d; 7392:c811, d811; 2c4e:0105.
- 8822CU: 0bda:c82c, c812, c82e, d820, d82b; 13b1:0043; 2001:3329.
- 8822BU: 0bda:b812, b82c, 2102, b81a; plus about 30 vendor IDs (7392, 0b05, 2001, 13b1, 2357, 0846, 0e66, 04ca, 20f4, 056e, 2c4e, 0411). The full list is in `rtw8822bu.c`.

What the USB host stack must provide (Linux API calls in usb.c):
- `usb_control_msg` vendor requests on EP0. Register read: bmRequestType 0xC0, bRequest 0x05, wValue = register address, wIndex 0, length 1/2/4, timeout 1000 ms. Write: 0x40 / 0x05. Burst writes go up to `RTW_USB_VENQT_MAX_BUF_SIZE` = 254 bytes.
  - Quirk for 8822C/8822B/8821C: after every read of an "always-on" register (0x00-0xFF or 0x1000-0x10FF), the driver also writes 1 byte to register 0x4e0 (`rtw_usb_reg_sec`).
- Endpoint parsing (`rtw_usb_parse`): exactly 1 bulk IN, 1-4 bulk OUT endpoints. An interrupt IN endpoint is recorded but never used. The OUT endpoint count selects `chip->rqpn_table[num_out_pipes]`, which maps QSEL to endpoint.
- Bulk IN: `RTW_USB_RXCB_NUM` = 4 URBs in flight, each with a 32768-byte buffer (`RTW_USB_MAX_RECVBUF_SZ`). One URB carries several aggregated frames, 8-byte aligned (`RTW_USB_RECVBUFF_ALIGN_SZ`).
- Bulk OUT: TX aggregation up to 20 KB (`RTW_USB_MAX_XMITBUF_SZ`). `usb_tx_agg_desc_num` = 3. The TX descriptor checksum is recomputed per aggregate.
- Firmware download and H2C go through bulk OUT as TX packets (`write_data_rsvd_page`, `write_data_h2c`). There is no IDDMA path as on PCIe.
- Device speed (`udev->speed`: SUPER / HIGH / FULL) sets the RX DMA burst size (1024 / 512 / 64) and the RX aggregation parameters.
- `usb_reset_device`: used by the USB2-to-USB3 mode switch, which applies to 8822C/8822B only, not 8821C. The driver writes `REG_PAD_CTRL2` and the device re-enumerates, so hotplug re-enumeration must work.
- Also needed: workqueues, skb queues, and spinlocks (simple equivalents are enough).
- Power-on difference: with the USB HCI, 8822C/B/8821C clear `REG_SYS_STATUS1+1` bit0 after the power sequence (mac.c:315).

## 4. Builder facts: Realtek Bluetooth (RTL8821C BT half over USB)

- btusb matches every Realtek BT device generically with `USB_VENDOR_AND_INTERFACE_INFO(0x0bda, 0xe0, 0x01, 0x01)`. It also lists explicit IDs. 8821CE BT, for example, includes 13d3:3529; 8822CE BT is 0bda:b00c and 0bda:c822.
- Transport: standard HCI USB. Commands go to EP0 (class request), events come on interrupt IN, ACL data on bulk IN/OUT. SCO isochronous transfers are only needed for audio.
- btrtl init sequence:
  1. `HCI_OP_READ_LOCAL_VERSION`, giving lmp_subver and hci_rev. 8821C is lmp_subver 0x8821, hci_rev 0xc, hci_ver 0x8, bus USB.
  2. Vendor cmd 0xfc6d reads the ROM version.
  3. Pick the firmware: `rtl_bt/rtl8821c_fw` + ".bin" (`snprintf "%s.bin"`, line 1205) and config `rtl_bt/rtl8821c_config.bin`. For 8821C over USB, config_needed=false.
  4. Parse the epatch. Signature is "Realtech" (v1) or "RTBTCore" (v2); select the patch for the ROM version, then append the config.
  5. Download with vendor cmd 0xfc20 in 252-byte fragments (`RTL_FRAG_LEN`). Byte 0 is the index; it wraps after 0x7f back to 1, and the last fragment has bit 0x80 set. Each fragment expects a Command Complete event of `sizeof(rtl_download_response)`.
- Firmware sizes: rtl8821c_fw.bin 54636 B, rtl8821c_config.bin 10 B.
